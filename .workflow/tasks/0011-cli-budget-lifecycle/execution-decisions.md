# Execution Decisions

## Publication decisions added 2026-10-03

- D7 (underspecified choice): register the initial encrypted file and encryption test together in the server upload handler. Older servers must advertise `encrypted-initial-publication` before the engine creates a publication identity. Alternative plaintext-first publication would expose the budget. Malformed initial-key tests and the real encrypted-reader fixture support this choice. Confidence: high. Additive server capability; no schema migration. Relationship: aligned. Review: pending independent review.
- D8 (design wall): retain the publication server, file ID, encryption mode, key test, and prepared/published state before uploading. A lost response requires inspecting the same identity before another upload. Alternative blind retry could create duplicates or overwrite a different budget. The proxy drops an accepted upload response, then recovery proves one upload and one identity. Confidence: high. Persistent metadata changes are omitted from exports/clones. Relationship: aligned. Review: pending independent review.
- D9 (underspecified choice): archive is a reversible device-local marker, disclosed in inventory. It does not delete remote data. Rename uses the existing synced preference writer. The alternative remote archive/delete would exceed the plan's preservation requirement. Packaged restart and independent-reader tests prove these semantics. Confidence: high. Relationship: aligned. Review: pending independent review.
- D10 (design wall): close the cached account database before the existing migration teardown removes its directory on Windows. Run the browser wrapper's inner Lage build because Bash startup is unavailable here. Focused server tests exit successfully after database closure. Confidence: high. No production database schema changes. Relationship: extends verification/platform cleanup. Review: pending independent review.
