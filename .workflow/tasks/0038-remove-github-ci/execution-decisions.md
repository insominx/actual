# Execution decisions: 0038 remove-github-ci

All decisions follow the owner's request of 2026-10-28 ("remove all github ci workflow stuff and fix why it is currently failing"). The owner was unavailable, so the agent made them; each is reversible from git history.

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                | Options / trade-off                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Status                         |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| D1  | Delete the workflow files instead of only disabling Actions in the repository settings.                                                                                                                                                                                                                                                                                                 | Deleting needs no admin token and stops the scheduled runs. Disabling Actions (Settings > Actions > General) is also reversible and would block workflows that a future sync re-adds, but it needs the owner's login. The two do not conflict, so the settings step is left to the owner as a belt-and-braces measure.                                                                                                                                                                                              | Adopted                        |
| D2  | Keep the workspace package `packages/ci-actions`.                                                                                                                                                                                                                                                                                                                                       | `packages/docs/scripts/generate-upcoming-release-notes.mjs` imports `@actual-app/ci-actions/src/release-notes/util.mjs`, and `yarn generate:news-feed` runs from the package. Its CI-only scripts stay as inert code, which keeps the package identical to upstream apart from one comment and avoids modify/delete conflicts on every sync. Delete it later if the docs import and the news feed are given up.                                                                                                     | Adopted                        |
| D3  | Widen the `packages/ci-actions` knip entry to `bin/*.{ts,mjs}`.                                                                                                                                                                                                                                                                                                                         | knip's GitHub Actions plugin only runs while `.github/workflows` holds YAML, and it was the only thing making four `ci-actions` scripts entry files. With the old `knip.json` on the post-removal tree, knip reports those four files as unused plus an unused `@octokit/rest`; with the new one it reports exactly what it reported before the removal. On this Windows checkout `yarn knip` exited 1 both before and after, on four unrelated `.husky` items (see D9); Linux CI was green on knip at `8d0941be9`. | Adopted                        |
| D4  | Keep the root devDependencies `@octokit/rest`, `minimatch` and `p-limit`, and ignore them in knip.                                                                                                                                                                                                                                                                                      | Only `.github/scripts/count-points.mjs` used them. Pruning them rewrites `yarn.lock` and edits `package.json` lines that upstream bumps often, so every later sync would conflict there (D14 of task 0037 already says to leave lockfile reconciliation to `yarn install`). The ignore costs one line in `knip.json`.                                                                                                                                                                                               | Adopted; prune later if wanted |
| D5  | Future upstream syncs drop changes under `.github/workflows`, `.github/actions`, `.github/scripts`, `.github/actionlint.yaml` and `.actrc`. The rule is in `AGENTS.md`.                                                                                                                                                                                                                 | A cherry-pick that adds a workflow applies cleanly and brings CI back: the 2026-10-27 sync added `publish-ios.yml` and `publish-mac-app-store.yml` that way (#9314, #9327, #9330), although D13 of task 0037 skips upstream CI infrastructure commits. Changes to files the fork deleted appear as modify/delete conflicts; resolve them with `git rm`. Disabling Actions in the repository settings is the only mechanical guard (D1).                                                                             | Adopted                        |
| D6  | The local gates are the source of truth: `yarn typecheck`, `yarn test`, `yarn constraints`, `yarn check:tsconfig-references`, `yarn knip`, and `yarn lint` (on Windows, `oxfmt --check` and `oxlint` on the changed files).                                                                                                                                                             | There is no PR bot, label, size report, translation upload or screenshot regeneration any more. VRT screenshots can only be regenerated with `yarn vrt:docker`, which needs Docker (this machine has none).                                                                                                                                                                                                                                                                                                         | Adopted                        |
| D7  | Skip the two upstream `atomic-write` symlink tests when the account cannot create symlinks.                                                                                                                                                                                                                                                                                             | They failed with `EPERM` on this unprivileged Windows account, so every local `yarn test` of `@actual-app/core` and `@actual-app/sync-server` was red. The probe is the one `packages/cli/src/jobs.test.ts` already uses. The tests still run on Linux, macOS and privileged Windows, but with CI gone they now run nowhere on this machine; Windows Developer Mode or WSL makes them run again.                                                                                                                    | Adopted                        |
| D8  | Leave upstream's own text about its CI untouched: the contributing guides in `packages/docs`, the sponsor badges, the CI-themed notes in `upcoming-release-notes/`, the `review-actual-pr` skill (it reviews upstream PRs, where the label automation still exists), the comment in `scripts/agent-hooks/git-guard.sh`, the "labeling" mention in `AGENTS.md`, and the issue templates. | They describe upstream's process and are published from upstream, not from this fork. Editing them would only add conflicts to later syncs. Statements about live behavior in the agent skills, the CLI architecture page, the migrations README and two comments were corrected instead.                                                                                                                                                                                                                           | Adopted                        |

| D9 | Check the husky hooks out with LF line endings: add `.husky/* text eol=lf` to `.gitattributes`. | The three hooks are extensionless shell scripts, which `.gitattributes` did not cover (it forces LF for `*.sh` and `**/bin/*`), so a Windows checkout got CRLF. That breaks shell scripts if the hooks are installed, and made knip read `nano-staged\r` and `install\r` as unlisted binaries: four findings and `yarn knip` exit 1 on every Windows checkout. One attribute line fixes both and changes nothing on Linux or macOS. An existing clone needs the three hooks rewritten with LF once (this clone was done). `yarn knip` now exits 0 here. | Adopted |
