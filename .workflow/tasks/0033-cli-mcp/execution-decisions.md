| D2  | No MCP SDK dependency was added. `src/mcp.ts` implements the MCP stdio transport directly (newline-delimited JSON-RPC 2.0): `initialize` (protocol 2025-06-18, 2025-03-26, 2024-11-05), `ping`, `tools/list` (paged), `tools/call`, `resources/list`, `resources/templates/list`, `resources/read` and `notifications/cancelled`. Interoperability is proven with the official `@modelcontextprotocol/sdk` 1.32.0 client installed outside the repository (`ACTUAL_TEST_MCP_SDK`). | The plan allows a pinned SDK, but adding it changes the lockfile and the CLI bundle for an optional surface; the subset needed for tools and resources is small and the official client accepts it. | ASSUMPTION for Michael to review                                     |
| D3  | Every registered leaf operation becomes one explicit tool (dots become underscores, e.g. `cash-planning_inspect`), with the input schema from `discoverOperations` plus positional arguments as properties. There is no generic execute tool. Excluded as CLI-only: `server init/start/stop/logs/bootstrap`, `sync watch`, `profiles set/use` and `mcp` itself. `--domains` narrows the exposed domains.                                                                           | Plan: explicit domain tools generated from the registry; long-running, lifecycle and credential commands do not belong in a tool call.                                                              | Adopted                                                              |
| D4  | A tool call runs the CLI itself (`process.execPath` with the serving `cli.js`, the forwarded global options and `--output-version 2`) as a child process and returns its envelope as `structuredContent` (text copy in `content`, `isError` on a non-zero exit). Budget selection and credentials come from the serve command's options and environment; tools never accept credentials.                                                                                           | Same executor, locks, journals and run records as the CLI, identical data (A1), and protocol stdout cannot be polluted by command output.                                                           | ASSUMPTION for Michael to review                                     |
| D5  | Inputs are validated against the generated schema (unknown properties, missing required properties and wrong types) before a child process starts; failures are JSON-RPC `-32602` errors.                                                                                                                                                                                                                                                                                          | Plan A2.                                                                                                                                                                                            | Adopted                                                              |
| D6  | `notifications/cancelled` terminates the child process and sends no response; closing stdin terminates in-flight children. A cancelled guarded change keeps whatever receipt state the journal recorded, and a cancelled workflow keeps its run record for `workflow run resume`.                                                                                                                                                                                                  | Plan: cancellation preserves operation and run status.                                                                                                                                              | Adopted                                                              |
| D7  | Annotations: `readOnlyHint` from the registry's `mutates`, `destructiveHint` from its `destructive`, `idempotentHint` for reads, `openWorldHint` false. Resources: `actual://domains`, `actual://operations` and `actual://schema/{tool}`.                                                                                                                                                                                                                                         | Plan: disclose read/write/destructive capability and give schema access.                                                                                                                            | Adopted                                                              |
