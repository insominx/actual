# Execution decisions: 0021 cli-imports

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Reason                                                                                | Status                           |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | -------------------------------- |
| D1  | Start on Linux acceptance of 0014, 0018, 0019 and 0020 (Windows reruns open).                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Same rule as the other dependents.                                                    | ASSUMPTION for Michael to review |
| D2  | File import is one core guarded operation, `imports.file`, that parses with `inspectImportFile` and delegates planning and commit to the existing `transactions.import` plan and acknowledgement check (`planTransactionImport`/`performTransactionImport`). No second import path, no new receipt format.                                                                                                                                                                                                                               | One owner for matching, rules and commit verification.                                | Adopted                          |
| D3  | The proposal freezes the file SHA-256, resolved settings and their sources, and resolved options. `reimportDeleted` is resolved from the account preference (`sync-reimport-deleted-<account>`, default true) at preview so it is explicit and part of staleness. Apply re-prepares (guardedApply), so a changed file, saved mapping, preference or affected ledger state returns `STALE_PREVIEW`. `--expect-sha256` (request `sha256`) additionally lets a direct apply reject a file that changed since a read-only `imports preview`. | Plan: apply verifies file hash, mapping and observed state; no blind replay.          | Adopted                          |
| D4  | Per-row match evidence comes from a second read-only `matchTransactions` run on the same normalized rows: `imported_id` (step 1), `payee_date_amount` (step 2) and `date_amount` (step 3). Outcome `update` means the matched row changes (it is in the plan's updates); `duplicate` means matched with nothing to change; `reconciled` and `deleted` come from the matched row's flags.                                                                                                                                                 | Distinct evidence for exact and heuristic matches without changing the engine.        | ASSUMPTION for Michael to review |
| D5  | Invalid rows reject the whole file by default; `invalidRows: skip` (`--skip-invalid`) imports the valid rows and lists invalid ones with their errors in the proposal and receipt. Files over 1000 rows are rejected (inspection row limit).                                                                                                                                                                                                                                                                                             | Mixed valid/invalid handled explicitly; the dialog stops at the first bad row.        | ASSUMPTION for Michael to review |
| D6  | Category text in a file resolves by exact name as the dialog does (`parseCategoryFields`); unmatched names import uncategorized and are listed in `summary.unresolvedCategories`. Notes are always imported (the dialog's default).                                                                                                                                                                                                                                                                                                      | Dialog parity, with the gap disclosed.                                                | ASSUMPTION for Michael to review |
| D7  | History is the device-local change journal filtered to `imports.file` (`imports history`), not a new store. Status of one import is `imports history --operation-id <id>` or `changes status <id>`. Imports made in the browser or on another device are not listed.                                                                                                                                                                                                                                                                     | Plan: device-local receipts through the mutation protocol, no tool-only budget state. | Adopted                          |
| D8  | `imports preview` maps engine rejections to `INVALID_INPUT` with the engine's message (the guarded `changes preview` path keeps its generic message).                                                                                                                                                                                                                                                                                                                                                                                    | Read-only previews should explain why a file cannot be imported.                      | ASSUMPTION for Michael to review |
| D9  | Multi-file intake (slice 3) is one guarded `imports apply` per file, each with its own receipt; overlap between files is caught by duplicate matching against rows committed by earlier files. No combined multi-file transaction.                                                                                                                                                                                                                                                                                                       | Per-file results and no hidden partial batch commit.                                  | ASSUMPTION for Michael to review |
