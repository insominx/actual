# Execution decisions: 0031 cli-workflows

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Reason                                                                                                                                              | Status                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| D1  | Start on Linux acceptance of the prerequisites (Windows reruns open).                                                                                                                                                                                                                                                                                                                                                                                                           | Same rule as the other dependents.                                                                                                                  | ASSUMPTION for Michael to review |
| D2  | Workflows live in the CLI (`src/workflows.ts`, `src/workflow-runs.ts`, `commands/workflow.ts`). Every step calls an existing public API read (`getDataQualityCheckup`, `findTransferCandidates`, `getReconciliationStatus`, `inspectSchedules`, `getBankSyncStatus`, `inspectCashPlan`) or an existing guarded-change executor (`budgets.create`, `accounts.create`, `category-groups.create`, `categories.create`, `imports.file`, `reconcile.finish`). No core or API change. | Plan: fixed definitions over the same typed operations; no separate finance logic.                                                                  | Adopted                          |
| D3  | Run records are device-local JSON files in `workflow-runs/` in the CLI data directory (budget, validated input, fixed step plan, step outcomes, operation IDs, unresolved items, artifacts). A mutation step fixes its operation ID (`<run-id>-<step>`) and exact payload and writes the record before executing, so a resumed step replays the change-journal receipt instead of mutating again.                                                                               | Plan A2; reuse the 0013 change journal for idempotency rather than a second receipt format.                                                         | Adopted                          |
| D4  | Running a workflow authorizes the mutations its plan lists (one run, not a prompt per operation). `monthly-close` finishes a reconciliation only with `--finish` and a zero difference; without it the matched account is an unresolved `reconcile-not-authorized` item.                                                                                                                                                                                                        | Plan: follow supplied instructions without redundant prompts; reconciliation locks rows, so it needs an explicit flag.                              | ASSUMPTION for Michael to review |
| D5  | `workflow setup` with `budgetName` creates a local budget and, like `budgets create`, requires `--offline`; it does not publish. Later steps and runs select the new budget with `--offline --budget-id`. Publication stays `budgets publish`.                                                                                                                                                                                                                                  | Reuse the existing budget creation contract (local creation and publication are separate operations).                                               | ASSUMPTION for Michael to review |
| D6  | Unresolved items: invalid import rows, rows matched only by date and amount, unresolved import categories, transfer candidates, data-quality warnings and errors, months with unknown coverage or a statement discrepancy, unmatched statements and missed schedules. A run with any of them ends `needs-review`, not `completed`. `summary.closeComplete` is true only when every statement in the close reconciled.                                                           | Plan contract: ambiguous imports, unmatched balances and unknown coverage stay explicit; incomplete reconciliation never reads as a complete close. | Adopted                          |
| D7  | `workflow goal-review` is read-only: it returns the saved plan and an optional transient scenario side by side and has no save flag. Saving stays `cash-planning save                                                                                                                                                                                                                                                                                                           | set-target                                                                                                                                          | set-goal` (guarded).             | Plan A3: scenarios change no saved plan until an explicit save; one save path. | ASSUMPTION for Michael to review |
| D8  | `--stop-after <step>` pauses a run. The packaged crash proof pauses after the second import and then rewrites that step to `pending` in the run record, which is the state a crash between the guarded commit and the record write leaves; resume replays the receipt and the row count is unchanged.                                                                                                                                                                           | Deterministic crash point without a test-only hook in production code.                                                                              | Adopted                          |
| D9  | Only one process advances a run: a per-run lock (the existing `lock.ts` gate) with about a one second wait; a second invocation fails with retryable `ENGINE_FAILURE` (`reason: run-active`). Cancel keeps committed steps and marks pending steps without a fixed payload `not-run`; a pending step with a fixed payload stays visible because it may have committed.                                                                                                          | Plan: accurate partial outcomes on cancellation; device-local lock only.                                                                            | Adopted                          |
| D10 | `workflow weekly-checkup` reads data quality for the previous and current month, schedules due within seven days of `--as-of`, and bank sync status. It never refreshes bank sync or posts schedules.                                                                                                                                                                                                                                                                           | Checkup is a read workflow; refresh and posting remain explicit commands.                                                                           | Adopted                          |
