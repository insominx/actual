# Execution decisions: 0017 cli-query

- D1 (ASSUMPTION for Michael to review, 2026-10-04): version 1 `query tables` and `query fields` keep their exact legacy JSON (the hand-written list, now named LEGACY_TABLE_SCHEMA) because section 9 preserves default legacy JSON. Version 2 output and all table validation use core metadata. The plan's "replace TABLE_SCHEMA consumers" is therefore met for version 2 and validation, not for legacy output.
- D2 (ASSUMPTION for Michael to review, 2026-10-04): `query run --table` now accepts every core schema table (for example notes, preferences, tags), not only the six legacy names. This only widens accepted input. Malformed `--filter` JSON now fails as INVALID_INPUT in both versions instead of a raw SyntaxError.
- D3 (2026-10-04): metadata and validation are pure API functions (no `send`), so discovery works without a budget, server or session. They read the same core schema and compiler the engine executes, so there is no second schema.
- D4 (ASSUMPTION for Michael to review, 2026-10-04): version 2 `query run` changes its data from a bare row array to `{ rows, page, snapshot }` so limits, truncation, order and continuation are disclosed (section 3). Version 1 output is unchanged. Count queries keep `{ count }`. Default page 1000 rows, maximum 10000.
- D5 (2026-10-04): the snapshot marker is the persistent-source fingerprint that guarded previews already bind (inspectCopySource). A first version used the CRDT message count and latest timestamp, but the API test showed local-only budgets do not record messages, so changes there went undetected. The fingerprint reads the persistent tables once per page, which costs more on large budgets but detects every committed change. Cached reads see another client's change only after a refresh, so agents paging across clients should pass --require-fresh (the packaged proof does).
- D6 (ASSUMPTION for Michael to review, 2026-10-04): the aggregate recipe groups by category only. Transfers (any row with transfer_id), starting balances (starting_balance_flag) and uncategorized rows are separate groups instead of being folded into categories; `--splits leaves` (default) counts split children, `parents` counts split parents, and the total is identical either way. Off-budget accounts are included unless `--account` narrows the scope. SQL writes are not reachable: the command only issues AQL selects and calculations.
- D7 (2026-10-04): core validateQuery rejects a condition object with more than one operator (ignoring $transform) because the compiler silently applies only the first. Execution of legacy version 1 queries is unchanged.
